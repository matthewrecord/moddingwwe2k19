## What is known about saves (static analysis, exe build 2021-03-30)
Details: `notes/characters/expand_509_scope_2026-11-10.md` (steps 1, 1e, 1f).
- Per-save copies: pointer 0x1425e69a8 -> 3 blocks of 0x1EA9C8 bytes. Block = 8-byte header + 509 pofos (0x1E4)
  at +8 + 509 movesets (0xD88) at +0x3C260. Getters 0x1409655a0 (pofo) / 0x1409655f0 (moveset) return the save copy
  for index < 0x1FD, otherwise null -> callers fall back to the main (file) arrays. Overflow slots therefore always
  read the file-defined data: in-game edits to them do not persist (by design of stage 1).
- The main block [0x1425e69b0] is a fixed-layout struct: 509 pofos, then other data at fixed offsets
  (+0x3C260 ..., CAW block +0x51A60 = 100 x 0x14B0, more at +0x448CEC); ~90 code sites address those offsets.
- Universe data (shows, rosters, titles, history, stats) has NOT been located yet. Unknown: where Universe stores
  per-superstar data, whether it is keyed by character id (0-1023, fine) or by profile index (509-wide: overflow
  slots would be dropped or overflow), and how title history / match records are kept (if at all).
- Code that loops over slots: 173 loop bounds of 0x1FD/0x1FC in the exe (`notes/characters/cap_constant_sites.txt`);
  many will be Universe/roster screens. Unpatched loops skip slots >= 509 silently.
