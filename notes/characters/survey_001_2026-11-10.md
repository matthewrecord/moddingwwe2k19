## Profile tables (pac/profile, HSPC -> SHDC)
- `profile_dat.pac`: **561 records x 488 bytes** (pofo: u16 8, u16 488, u16 slot id @+4, ...). Base already holds ids
  up to 999, incl. placeholder ids 860-999 with duplicates (950-959 twice) -> the game ships with more table rows
  than playable characters.
- `profile_pro.pac` / `profile_mvs.pac` (BPE-compressed records): base **459** entries; profile_dat_p10/_p30 are
  small patch tables (ids 256).
- **PerfectPlextra 1.4b** (mods/PerfectPlextra/pac/profile, 3 files) = make all 561 profile_dat ids distinct (900-999
  block) and add pro/mvs entries 459..560 (stored uncompressed). So it did NOT create new table capacity: it activated
  the ~100 dormant rows the game already had. With PPX installed, all 561 rows are in use.

## What this means
- Under 561 rows, "new" character slots = repurposing rows (Unused/Hidden/AVAILABLE ones, as Matthew does).
- Beyond 561 = appending rows to profile_dat/pro/mvs. Unknown whether the game sizes its arrays from the file count
  or has a fixed cap (CCT's memory addresses: superstar pofo block 0x142840600, CAW pofo 0x142892060: gap
  0x51A60 = 691 x 484 bytes, suggesting room for ~691 pofos if nothing else sits between; unverified).
- Ids are u16; ids below 1000 not used by any row: many (900 possible ids 100-999 vs 561 rows), so new rows could
  keep 3-digit ids (file names like ch<id>, renders 0NNN00 likely assume 3 digits).
- Select screen: separate menu list (Wrestleminus edits it). Likely the same kind of list as the CAE BGM.lsd we
  solved, possibly with the same unlock-requirement fields -> explains "AVAILABLE GFX" slots that would not become
  Selectable. To check next.
